# Building, signing and testing Board

This page holds the build detail that used to sit at the top of the README. What was observed on real machines, release by release, is in [the verification ledger](VERIFICATION.md).

## Build and run

Open `Board.xcodeproj`, select the **Board** scheme and **My Mac**, then Run. The project has one app target and one XCTest target and uses only Apple frameworks. Xcode's own builds are ad-hoc signed.

From a checkout:

```sh
bash Scripts/build.sh
```

The packaged app is `dist/Board.app`. Build output and previous packages stay inside `build/`. The build installs nothing into `/Applications`, registers no login item, grants no permission and changes no developer setting.

The Xcode project is generated by `Scripts/generate_project.py`. Run it after adding or removing source files.

## Signing

`Scripts/build.sh` signs the package with the keychain's **Developer ID Application** identity, hardened runtime and a secure timestamp. If there is none, it uses a local identity or an ad-hoc signature and prints a warning: such a build runs only on the Mac that built it. To choose an identity, set `BOARD_CODESIGN_IDENTITY` to its SHA-1 hash or full name.

The signature matters for Input Monitoring. macOS ties the permission to the app's identifier and signing identity, so a Developer ID build keeps its permission when you replace it with a newer one. An ad-hoc signature changes with every build, and the permission has to be granted again.

## Notarize for other Macs

```sh
bash Scripts/build.sh --notarize
```

This needs the Developer ID identity. It uploads a ZIP of `dist/Board.app` to Apple's notary service and waits up to an hour. If Apple rejects it, the script prints Apple's log and stops. If Apple accepts it, the script staples the ticket to `dist/Board.app` and checks the result with `stapler validate` and `spctl -a -vvv -t exec`. Builds without `--notarize` never contact Apple.

One-time setup: store notarytool credentials in the keychain under the profile name `board-notary` (or set `BOARD_NOTARY_PROFILE` to another name):

```sh
xcrun notarytool store-credentials board-notary --apple-id <your Apple ID email> --team-id <TEAM_ID>
```

`<TEAM_ID>` is the ten characters in parentheses after the Developer ID Application name in `security find-identity -v -p codesigning`. notarytool then asks for an app-specific password; Apple explains how to create one in [Sign in to apps with your Apple Account using app-specific passwords](https://support.apple.com/en-us/102654). By default, notarytool checks the credentials with Apple before saving them.

To make the file for a release, zip the stapled app so the signature and the ticket survive:

```sh
ditto -c -k --keepParent dist/Board.app Board-<version>.zip
```

## The build refuses to post events

Board only listens to the keyboard and mouse. `Scripts/build.sh` fails if the app links any API that posts events into other apps, so AI mode can never type into your apps by accident.

## Tests

```sh
bash Scripts/test.sh
```

The tests cover:

- input transitions and shortcuts, keyboard geometry, sample selection and held-release association, versioned settings, import validation;
- visualizer timing and the keystroke trail (15-key limit, repeat counts, expiry, afterglow, movement in every placement);
- offline stereo and limiter output;
- AI mode (key mapping, pacing, coding along only while an agent works, no event posting);
- Practice (scoring, corrections, time limits, pause and resume, Secure Input, Unicode composition through native text input, saved results, off-screen rendering);
- Gaming practice (cue timing and scoring for every drill, native key and mouse input, pausing, history and best scores, the overlay's hold times, off-screen rendering);
- the two launch rules: Settings opens at launch only for onboarding or a missing permission, and nothing but Board builds the app's main menu.

Practice's and Gaming's rendering tests write their screenshots to `/private/tmp/board-practice-artifacts/` and `/private/tmp/board-gaming-artifacts/`. The gaming engine in `Board/Gaming/` also builds as its own Swift package: `swift test` runs its tests without the app.

Still checked by hand: window focus changes, the menu shortcut, a real Secure Input change, the overlay over full-screen games and audible playback in Practice. The test of Gaming's Start and Pause buttons through accessibility is skipped, because an off-screen window exposes no buttons.

Results, measured idle CPU, remaining hardware checks and known limitations are in [VERIFICATION.md](VERIFICATION.md).

## Where Board keeps things

- Settings: `UserDefaults` under `com.tommyent.Board`.
- Imported sounds: copied to `~/Library/Application Support/Board/Imported Audio/`.
- Practice and Gaming history: result summaries in `UserDefaults` (`practice.history.v1`, `gaming.history.v1`).
- No key-event history is kept anywhere.

No application code opens a network connection. Only `bash Scripts/build.sh --notarize` uploads anything, and only the built app, to Apple's notary service.

## Assets and development scripts

- [Asset inventory](asset-manifest.json): origin, author, revision or date, SHA-256 and processing of every bundled sound.
- [Original recording guide](RECORDING.md): an archived plan for recording more packs. Those sounds are not in the current catalog.
- [Design and reference notes](REFERENCES.md).
- `Assets/Source/`: editable artwork sources.
- `Board-Keycap-Brand-Package.zip`: the brand package (icons, logos, guide, fonts). The app uses its Porcelain `.icon`, five Dock ICNS files and the menu bar glyph.
- `Docs/References/`: source notices and reference material, separate from shipped resources.
- `Docs/images/`: the README's pictures, rendered off screen from the app's own views.

`Scripts/fetch_assets.py` is an optional development script that uses the network, pinned to a specific kbsim revision. It is not bundled with or run by the app. Every asset the app needs is already checked in, and ordinary builds are offline.
